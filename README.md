# QA Portfolio Hub

> **💡 本リポジトリの目的**
> 
> 本リポジトリは、採用担当者様の参考資料として、私のQAエンジニア転職に向けた技術習得状況や、面接での想定質問に対する回答等を、事前にドキュメントとして公開しているものです。目的は以下の2点です。
> 
> 1. **意思と前提条件の正確な伝達**
>    面接当日の限られた時間やその場のやりとりだけでは、自身のキャリアに対する考え方や、想定している勤務条件を100%正確に伝えることは困難です。事前にテキストとして可視化しておくことで、認識の齟齬をなくすことを目的としています。
> 
> 2. **採用活動におけるミスマッチ防止**
>    私の現在のスキルセットや、育児との両立を目指した希望勤務条件（猶予期間を設けた上での原則リモートワーク等）をあらかじめ開示しております。企業様が求める人物像や要件と照らし合わせて選考の初期段階でご判断いただくことで不要な面接の発生を防ぎ、私よりも優秀な人材を求める企業様・採用担当者様に対して、選考の手間をおかけしないようにすることを目的としています。

## 📝 Recent Learning Logs

- **2026-09-01 22:24**: 浮動小数点数の「情報落ち」問題は、2進数の筆算を行わず次の2段階フィルターで判断する。①「絶対値の小さい数（負の指数）同士を先に計算しているか」で大＋小を計算している選択肢を除外する。②カッコ内の演算結果により大きい数（2^5）との指数差が仮数部の保持可能桁数（7ビット）以内に収まるかを確認する。足し算で桁繰り上がりが生じ、指数差が8から7へ縮まる選択肢が正解となる。本質は「小さい順の計算」と「指数差の縮小」の確認のみである。
- **2026-08-31 00:52**: AP試験科目Bで捨てる問題を決めた。 ①ストラテジ系：QA転職・SC合格に直結しない、②組込み開発：目指すキャリアと無関係、③アルゴリズム：問われるスキルがAIで代替可能、④システムアーキテクチャ：いずれ学びたい内容だけど範囲が広すぎて試験対策上リスクが大きい。以上4分野はテキストを一切読まず完全排除する。一方、残り7分野（セキュリティ、NW、DB、情報システム開発、PM、SM、監査）を緑本等で徹底対策し、当日は全体をさらっと見た感触で解きやすい問題を選択する。

- **2026-08-28 22:42**: OC曲線（検査特性曲線）は、全数検査が不可能な場合に「何個抜き取って検査すれば十分か（サンプル数）」という検査ルールの精度を設計・決定するために使う。ロットの不良率に応じた合格確率を可視化したもので、不良率が極端に低い（100%付近）・高い（0%付近）領域では確率の偏りにより変化が平らになり、全体のグラフはS字カーブを描く。

## 💬 Interview FAQ

### Q: 就職したらどのように貢献できるか？
A: セキュリティスペシャリスト(SC)の知識を活かし、JSTQBの標準的なテスト技法に基づいて、Playwrightを活用したテスト自動化を構築できます。

### Q: 勤務形態に関して合意が必要な条件はあるか？
A: 育児（幼稚園の送迎等）と両立できるよう、内定承諾の段階で「キャッチアップ期間（就職後3ヶ月上限）終了後は、原則リモートワーク」および「フレックス制（コアタイムが13:30までに終了する、またはコアタイムなし）」が労働条件通知書等の書面で確認・合意できていることを前提としております。書面にて合意することで、入社後のミスマッチを防止したいと考えております。

### Q: なぜ37歳実務未経験でITエンジニアを目指すに至ったのか？
A: 現職の業務効率化のためにExcelマクロを使うようになり、プログラミングが楽しいと感じて仕事にしたいと考えたのが始まりです。当初は、「いつか個人開発や案件で生計を立てられたらいいな」という程度の考えで、転職時期については深く考えずに、趣味レベルで独学を続けていました。しかし、子どもが生まれたことをきっかけに、育休終了後の生活について夫婦で話し合った結果、「育児（幼稚園の送迎等）と両立できる仕事への転職」が最適であるという結論に至りました。そこで、もともとなりたいと思っていたITエンジニアへの挑戦を決め、自分に合いそうな職種として、セキュリティに強いQAエンジニアというポジションを目指すことにしました。
