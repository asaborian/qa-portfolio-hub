# QA Portfolio Hub

> **💡 本リポジトリの目的**
> 
> 本リポジトリは、採用担当者様の参考資料として、私のQAエンジニア転職に向けた技術習得状況や、面接での想定質問に対する回答等を、事前にドキュメントとして公開しているものです。目的は以下の2点です。
> 
> 1. **意思と前提条件の正確な伝達**
>    面接当日の限られた時間やその場のやりとりだけでは、自身のキャリアに対する考え方や、想定している勤務条件を100%正確に伝えることは困難です。事前にテキストとして可視化しておくことで、認識の齟齬をなくすことを目的としています。
> 
> 2. **採用活動におけるミスマッチ防止**
>    私の現在のスキルセットや、育児との両立を目指した希望勤務条件（猶予期間を設けた上での原則リモートワーク等）をあらかじめ開示しております。企業様が求める人物像や要件と照らし合わせて選考の初期段階でご判断いただくことで不要な面接の発生を防ぎ、私よりも優秀な人材を求める企業様・採用担当者様に対して、選考の手間をおかけしないようにすることを目的としています。

## 📝 Recent Learning Logs

- **2026-08-28 22:42**: OC曲線（検査特性曲線）は、全数検査が不可能な場合に「何個抜き取って検査すれば十分か（サンプル数）」という検査ルールの精度を設計・決定するために使う。ロットの不良率に応じた合格確率を可視化したもので、不良率が極端に低い（100%付近）・高い（0%付近）領域では確率の偏りにより変化が平らになり、全体のグラフはS字カーブを描く。
- **2026-08-27 23:36**: React/Next.jsなどのフロントエンド開発における単体・結合テストのデファクトスタンダードは「Vitest + happy-dom + Testing Library + jest-dom」の4点セットである。汎用テストランナーのVitestはバックエンド（Node.js）のテストも実行可能だが、フロントエンドではJSDOMより軽量高速なhappy-dom、ユーザー視点のTesting Library、直感的な検証を行うjest-domを組み合わせることで、画面表示やコンポーネント間の連携（結合）までをメモリ上で高速かつ一貫して検証できる。
- **2026-08-27 01:25**: 転職エージェントに頼っても、年齢/実務経年無し/リモート必須といった属性から短絡的に判断され、担当者からの手厚いサポートを受けにくいかもしれないと気づいたため、Findy等のプラットフォームを利用する戦略に切り替え。ポートフォリオアプリはまだ未完成だが、FindyのAI解析を想定し、先に最低限のCI/CD構築だけは行うこととする。今は資格取得を最優先、AP/SC/JSTQBを一発合格し、来年のJSTQB受験後5月から8月までの期間で一気にポートフォリオを仕上げる覚悟と方針を固めた。
- **2026-08-26 22:54**: パテントプールとは複数の特許をまとめて管理し企業間のライセンス手続きを楽にする仕組みのこと。開発のきっかけを作った特許権者であっても、その技術が最終的な製品規格に含まれなければライセンス料はもらえない。
- **2026-08-26 00:32**: フィージビリティスタディ（実現可能性調査）とは、新規事業やシステム開発の本格着手前に、技術・経済・運用・法的な実現可能性を事前検証し、リスク最小化と投資判断（Go/No-Go）を行う手法である。

## 💬 Interview FAQ

### Q: 就職したらどのように貢献できるか？
A: セキュリティスペシャリスト(SC)の知識を活かし、JSTQBの標準的なテスト技法に基づいて、Playwrightを活用したテスト自動化を構築できます。

### Q: なぜ37歳実務未経験でITエンジニアを目指すに至ったのか？
A: 現職の業務効率化のためにExcelマクロを使うようになり、プログラミングが楽しいと感じて仕事にしたいと考えたのが始まりです。当初は、「いつか個人開発や案件で生計を立てられたらいいな」という程度の考えで、転職時期については深く考えずに、趣味レベルで独学を続けていました。しかし、子どもが生まれたことをきっかけに、育休終了後の生活について夫婦で話し合った結果、「リモートワークができる企業への転職」が最適であるという結論に至りました。そこで、自分に合いそうな職種として、セキュリティに強いQAエンジニアというポジションを目指すことにしました。

### Q: 具体的にどのような勤務形態を想定しているか？
A: 原則リモートワーク、かつ早朝や夜間を含めた柔軟な時間調整が可能な働き方を希望しております。採用後最初の3ヶ月間を上限として、職場のルールや基本業務をキャッチアップするための期間であれば、出社可能です。それ以降は、子どもの幼稚園の送り迎えのため、原則リモートワークへ移行する必要があります。なお、リモート移行後も、月1回程度の頻度や、事前に調整ができるスケジュールであれば、家族と調整のうえ出社可能です。リモート移行後の普段の働き方としては、例えば、次のような形であれば可能です。

* **5:00 ~ 7:00 2時間勤務**
  (8:30前後に幼稚園送り)
* **9:00 ~ 13:00 4時間勤務**
  (14:00前後に幼稚園迎え)
* **20:00 ~ 22:00 2時間勤務**
* **合計: 8時間勤務**

幼稚園のお迎え以降は日中の業務復帰ができないため、「コアタイムが13:30までに終了する制度」または「コアタイムなし（フルフレックス）」での勤務を想定しております。
帰宅後は子どもが家にいるため、20時頃までは業務に専念する時間（勤務時間）にはカウントできないものと考えております。ただし、その時間帯もスマートフォン等での急ぎのご連絡には随時対応可能ですので、チームの業務進行に支障が出ないよう配慮します。子育ての都合で毎日決まって同じ時間に働くことは難しいかもしれませんが、状況に応じて妻や実家のサポートを受けながら、月の総労働時間をしっかりと確保いたします。
