## 📝 Recent Learning Logs

- **2026-09-26 23:17**: モジュール強度（凝集度）とモジュール結合度についての理解。モジュール強度はモジュール内部の要素同士の関連性の強さを表し、単一の機能や特定のデータ構造に特化しているほど強度が高く（機能的強度・情報的強度など）、保守性や再利用性が向上する。一方、モジュール結合度はモジュール間の依存関係の強さを表し、他モジュールへの影響を最小限に抑えるため低い（疎結合である）ことが望ましい。ソフトウェア設計においては「高凝集・疎結合（高強度・低結合）」を目指すことが基本原則である。
- **2026-09-26 22:07**: 2桁の2進数の上の桁を A、下の桁を B とすると、元の数は (2 × A + B) と表せる。これを 2 で割って切り捨てると (2 × A + B) / 2 = A + (B / 2) となる。ここで B は 0 か 1 なので (B / 2) は 0 か 0.5 になり、端数を切り捨てることで B の影響が消えて上の桁 A だけが残る。
- **2026-09-26 00:37**: 水平垂直パリティの誤り制御能力は、誤り訂正が1ビットのみ可能であり、誤り検出は奇数ビット（1, 3, 5ビット…）または2ビットの誤りに対して可能である。4ビット誤りのように、すべての行および列で偶数個の反転が同時に発生するパターン（2行×2列の長方形配置）でのみ検出漏れが生じる。
- **2026-09-24 00:13**: HTTPプロトコル自体はGETやPOSTのほかにPUTやDELETEなど多様なメソッドを定義しているが、HTMLの <form> タグは仕様上GETとPOSTしかサポートしていない。そのためNext.jsなどのフレームワークでは、通信レベル（TCP/IPのアプリケーション層）ではPOSTとしてデータを送信しつつ、フォーム内の隠しデータやミドルウェアによって内部でPUTやDELETEとして解釈・ルーティングする手法（Form Method Overriding等）が用いられている。また、Server Actions等の機能によりこれらの通信制御が抽象化・隠蔽されており、開発者はHTTP通信を直接意識することなく関数呼び出しのような記述でデータ操作を行えるようになっている。

## 💬 Interview FAQ

### Q: 就職したらどのように貢献できるか？
A: セキュリティスペシャリスト(SC)の知識を活かし、JSTQBの標準的なテスト技法に基づいて、Playwrightを活用したテスト自動化を構築できます。

### Q: どのような企業形態・契約形態を希望しているか？
A: 育児（幼稚園の送迎等）と両立可能な環境であることを前提に、広く機会を探しております。SaaS・SIer・QA専門企業といった事業形態や、正社員・業務委託等の契約形態にはこだわりません。第一希望としては、育児のゆとりや自己学習の時間を設けやすい**短時間（週20時間程度や時短）でのスタート**ですが、フルフレックス制度等で時間の調整が可能であれば、**最初からフルタイム（1日8時間稼働）での参画**も喜んでお受けいたします。具体的には、内定・契約時に以下の点が書面で確認・合意できることを前提としております。

1. **原則リモートワーク**
   * オンボーディングに伴う出社期間は入社後最大3ヶ月間とし、それ以降は原則リモートワークへ移行すること。
   * リモート移行後も月1回程度の出社や緊急時の対応は可能ですが、高頻度な定例出社（週1回・隔週等）がないこと。
2. **勤務時間の柔軟性**
   * 13:30以降はコアタイム等の拘束がないこと。早朝・午前・夜間等、育児中ではない時間帯で総労働時間を確保できること。

書面にて合意することで、入社後のミスマッチを防止したいと考えております。

### Q: なぜ37歳実務未経験でITエンジニアを目指すに至ったのか？
A: 現職の業務効率化のためにExcelマクロを使うようになり、プログラミングが楽しいと感じて仕事にしたいと考えたのが始まりです。当初は、「いつか個人開発や案件で生計を立てられたらいいな」という程度の考えで、転職時期については深く考えずに、趣味レベルで独学を続けていました。しかし、子どもが生まれたことをきっかけに、育休終了後の生活について夫婦で話し合った結果、「育児（幼稚園の送迎等）と両立できる仕事への転職」が最適であるという結論に至りました。そこで、もともとなりたいと思っていたITエンジニアへの挑戦を決め、自分に合いそうな職種として、セキュリティに強いQAエンジニアというポジションを目指すことにしました。
