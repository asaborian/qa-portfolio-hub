> **💡 本リポジトリの目的**
> 
> 本リポジトリは、採用担当者様の参考資料として、私のQAエンジニア転職に向けた技術習得状況や、面接での想定質問に対する回答等を、事前にドキュメントとして公開しているものです。目的は以下の2点です。

>

>    私の現在のスキルセットや、育児との両立を目指した希望勤務条件（猶予期間を設けた上での原則リモートワーク等）をあらかじめ開示しております。企業様が求める人物像や要件と照らし合わせて選考の初期段階でご判断いただくことで不要な面接の発生を防ぎ、私よりも優秀な人材を求める企業様・採用担当者様に対して、選考の手間をおかけしないようにすることを目的としています。

## 📝 Recent Learning Logs

- **2026-08-18 23:00**: プロジェクトマネジメントのクラッシングやファストトラッキングは、単なる工期短縮手法ではなくコスト増加や手戻りリスクとのトレードオフである。特にファストトラッキングはやり直しによる現場疲弊を招くため、なぜそのリスクを取るのかという背景の丁寧な説明と、チームメンバーとの納得感ある合意形成が不可欠である。
- **2026-08-17 21:41**: useStateは初期値から型推論されるが、errorMessageのように初期値nullから後で文字列を入れる場合は<string | null>と型拡張が必要。ただし、formData等のinput値は、value={null}を渡すとReactが制御を放棄して非制御（ブラウザDOM管理）と判定し、入力時に非制御コンポーネントから制御コンポーネントに変わり警告バグの原因となるため、nullは使用せず空文字（''）とし、制御コンポーネントとして一貫させる。
- **2026-08-16 14:16**: Webアプリの処理構造は、①UI描画（app/setup/page.tsxのJSX）と②入力保持・イベントハンドラ（app/setup/page.tsxのuseStateやhandleSubmit）が「ビュー（View）」、③入力値を受け取りDB処理を呼ぶServer Action（app/setup/actions.ts）が「コントローラ（Controller）」、④DB操作処理（db/users.ts）が「モデル（Model）」に分類できる。
- **2026-08-15 23:13**: TypeScriptのcatch(error)で捕捉されるエラーはunknown型となるため、そのままerror.messageを参照すると型エラーとなる。if (error instanceof Error)による型ガードを行うことで、実行時チェックと型の絞り込みを同時に実現し安全にプロパティへアクセスできる。また、elseブロックで予期せぬエラー（ネットワーク障害やシステムエラー等）を安全に捕捉することで、アプリのクラッシュや生のエラー露出による情報漏洩・ユーザーの混乱を防ぐ防御的プログラミングとなる。
- **2026-08-15 23:03**: JavaScript/TypeScriptでは、オブジェクトのプロパティ名と代入する変数名が全く同じ場合、コロン以降を省略して { name, department } のように短縮記述できる（プロパティ初期化子の短縮記法）。これにより同じ単語の繰り返しを避けてコードを簡潔にし、タイポによるバグを抑止できる。適用条件はプロパティ名と変数名が完全一致していることであり、名前が異なる場合は従来の { name: userName } 表記が必要となる。

## 💬 Interview FAQ

### Q: 就職したらどのように貢献できるか？
A: セキュリティスペシャリスト(SC)の知識を活かし、JSTQBの標準的なテスト技法に基づいて、Playwrightを活用したテスト自動化を構築できます。

### Q: なぜ37歳実務未経験でITエンジニアを目指すに至ったのか？
A: 現職の業務効率化のためにExcelマクロを使うようになり、プログラミングが楽しいと感じて仕事にしたいと考えたのが始まりです。当初は、「いつか個人開発や案件で生計を立てられたらいいな」という程度の考えで、転職時期については深く考えずに、趣味レベルで独学を続けていました。しかし、子どもが生まれたことをきっかけに、育休終了後の生活について夫婦で話し合った結果、「リモートワークができる企業への転職」が最適であるという結論に至りました。そこで、自分に合いそうな職種として、セキュリティに強いQAエンジニアというポジションを目指すことにしました。

### Q: 具体的にどのような勤務形態を想定しているか？
A: フルフレックスの原則リモートワークを想定していますが、採用後最初の3ヶ月間を上限として、職場のルールや基本業務をキャッチアップするための期間であれば、出社可能です。それ以降は、子どもの幼稚園の送り迎えのため、原則リモートワークの勤務形態へ移行する必要があります。なお、リモート移行後も、月1回程度の頻度や、事前に調整ができるスケジュールであれば、家族と調整のうえ出社可能です。リモート移行後の普段の働き方としては、例えば、次のような形であれば可能です。

* **5:00 ~ 7:00 2時間勤務**
  (8:30前後に幼稚園送迎)
* **9:00 ~ 13:00 4時間勤務**
  (14:00前後に幼稚園送迎)
* **20:00 ~ 22:00 2時間勤務**
* **合計: 8時間勤務**

なお、14時から20時頃は子どもが家にいるため、業務に専念する時間（勤務時間）にはカウントできないものと考えております。ただし、その時間帯もスマートフォン等での急ぎのご連絡には随時対応可能ですので、チームの業務進行に支障が出ないよう配慮します。子育ての都合で毎日決まって同じ時間に働くことは難しいかもしれませんが、状況に応じて妻や実家のサポートを受けながら、月の総労働時間をしっかりと確保いたします。
