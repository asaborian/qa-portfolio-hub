## 📝 Recent Learning Logs

- **2026-10-23 06:30**: リバースエンジニアリングは、既存ソフトウェアの動作やソースプログラムを解析し、製品の仕組みや構造、設計図などの情報を得る手法である。実行ファイルや動作から内部のコードを推測するアプローチだけでなく、既存のソースプログラムを解析してプログラム仕様書を復元するアプローチも含まれる。
- **2026-10-21 17:27**: 直接アドレス指定：アドレス部の値 ＝ 有効アドレス。間接アドレス指定：アドレス部の値が示すメモリ内の値 ＝ 有効アドレス。指標（インデックス）アドレス指定：アドレス部の値 ＋ インデックスレジスタの値 ＝ 有効アドレス。基底（ベース）アドレス指定：アドレス部の値 ＋ ベースレジスタの値 ＝ 有効アドレス。相対アドレス指定：アドレス部の値 ＋ プログラムカウンターの値 ＝ 有効アドレス。即値アドレス指定：アドレス部の値 ＝ 有効アドレスではなく、そのまま演算対象データとする。
- **2026-10-20 21:23**: 成長マトリクス（アンゾフの成長マトリクス）とは、企業が事業成長やマーケティング戦略を検討するためのフレームワークである。「市場」と「製品」のそれぞれを「既存」と「新規」の2軸に分類し、4つの戦略（市場浸透：既存製品×既存市場、新製品開発：新規製品×既存市場、市場開拓：既存製品×新規市場、多角化：新規製品×新規市場）にマッピングして事業展開の方向性を決定する。
- **2026-10-20 21:18**: IPv4のクラスフルアドレッシングにおけるクラスA〜Dは、第1オクテットの先頭ビットによって識別される。クラスAの先頭ビットは「0」（第1オクテット：0〜127）、クラスBは「10」（第1オクテット：128〜191）、クラスCは「110」（第1オクテット：192〜223）、クラスDは「1110」（第1オクテット：224〜239、マルチキャスト用）である。また、クラスCの範囲内におけるグローバルIPアドレスとプライベートIPアドレスの識別は、第1オクテットの「192」と第2オクテットの「168」の組み合わせ（192.168.0.0/16）によってプライベートIPアドレスとして規定されていることにより決定され、これに該当しないクラスCの残りの領域はすべてグローバルIPアドレスとして扱われる。
- **2026-10-18 11:49**: VercelとNeonを用いた環境分離では、ローカルの .env.local に開発用（development）の DATABASE_URL や CLERK_SECRET_KEY を配置し、Vercelの管理画面には本番用（production）の DATABASE_URL や各種鍵を配置することで接続先を完全に分離する。またマイグレーションにおいて、開発時はターミナルから手動でコマンドを実行して development DBに反映し、本番時は GitHub の main マージ時に Vercel が schema.ts の差分を検知して自動で production DBに適用する。

## 💬 Interview FAQ

### Q: 就職したらどのように貢献できるか？
A: セキュリティスペシャリスト(SC)の知識を活かし、JSTQBの標準的なテスト技法に基づいて、Playwrightを活用したテスト自動化を構築できます。

### Q: どのような働き方・契約形態を希望しているか？
A: SaaS、SIer、QA専門企業等の事業形態や、正社員・業務委託・スポット（短期）案件といった契約形態を問わず、幅広く機会を探しております。長期的な参画はもちろん、プロジェクト単位の関わり方も含めて柔軟に対応可能です。

**稼働・スケジュールに関するご相談**
* **オンボーディング（入社後最大3ヶ月間）:** フル出社可能です。
* **通常稼働（オンボーディング完了後）:** 原則リモートでの運用を希望いたします（月1回程度の定例出社であれば、事前に家族と調整のうえ対応いたします）。
* **2029年1月以降（妻の復職後）:** 毎日14:00〜18:00頃が自宅でのワンオペ育児時間となります。リモートワークおよびフレックス等でこの時間の調整（中抜けや時間振替）が可能であれば、**1日4時間の短時間から8時間フルタイムまで幅広く対応可能**です。
* **緊急対応:** ワンオペ育児中も連絡は繋がる状態です。緊急の際は、状況に応じて柔軟に対応いたします。

※上記の働き方が可能な勤務条件（出社頻度月一回、コアタイムなし等）について、内定・契約時に書面等で確認・合意させていただけますと幸いです。

### Q: なぜ37歳実務未経験でITエンジニアを目指すに至ったのか？
A: 現職の業務効率化のためにExcelマクロを使うようになり、プログラミングが楽しいと感じて仕事にしたいと考えたのが始まりです。当初は、「いつか個人開発や案件で生計を立てられたらいいな」という程度の考えで、転職時期については深く考えずに、趣味レベルで独学を続けていました。しかし、子どもが生まれたことをきっかけに、育休終了後の生活について夫婦で話し合った結果、「育児（幼稚園の送迎等）と両立できる仕事への転職」が最適であるという結論に至りました。そこで、もともとなりたいと思っていたITエンジニアへの挑戦を決め、自分に合いそうな職種として、セキュリティに強いQAエンジニアというポジションを目指すことにしました。
