> 
> 本リポジトリは、採用担当者様の参考資料として、私のQAエンジニア転職に向けた技術習得状況や、面接での想定質問に対する回答等を、事前にドキュメントとして公開しているものです。目的は以下の2点です。

## 📝 Recent Learning Logs

- **2026-08-10 07:55**: form action（Server Component）ではなく、あえてコードの長い use client で書く理由: Next.js 14 以降は HTML 標準の form action を使えば 'use client' なし（Server Component）で簡潔にフォーム送信を書ける。しかし、form action だけだとクライアント上で完結せず、一度サーバーに投げるため、「未入力のまま送信しようとしたときの'必須項目が空欄です'といった警告表示がもたつく」「送信中にボタンを押した感がなく、連打されてしまう」といった不便さが発生する。'use client' を使うことで、「画面をリロードさせずに赤文字で即座にエラーを出す」「送信中のボタン連打を防ぐ」といった、ユーザーが迷わず安全に使える快適な操作性（UX）を実現できる。
- **2026-08-09 22:16**: IdPにおいて、『このユーザーは本人です』という証明書（XML）をSPへ送るための標準ルール（プロトコル）がSAML
- **2026-08-09 00:18**: SQLのr1やr2は同じテーブルを2役で使う際につけるあだ名（別名）で、上部のSELECTで突然使われているように見えても中盤のFROM句で定義されており、SQL内部ではFROMから順に処理されるため破綻していない。INNER JOIN（内部結合）は両方のテーブルに存在する共通データだけを抽出する結合方法である。ROW_NUMBER()は指定順に重複のない連番（1, 2, 3…）を振る関数で、PARTITION BY（グループ分け）と組み合わせることで「部署やカテゴリ等のチームごとに番号を1から振り直す」処理ができる。
- **2026-08-07 18:43**: throwはエラーを投げるだけでなく、関数内で次の行以降の処理を中止する / throwはtry...catchとセットで使う / page.tsx上でtry...catchを書き、try内で呼び出した関数の中身として、actions.ts上でthrowを書く / throwから見て直属の呼び出し元にtry...catchが無くても、どんどん上の階層にtry...catchが見つかるまで探して行って渡される

## 💬 Interview FAQ

### Q: 就職したらどのように貢献できるか？
A: セキュリティスペシャリスト(SC)の知識を活かし、JSTQBの標準的なテスト技法に基づいて、Playwrightを活用したテスト自動化を構築できます。

### Q: なぜ37歳実務未経験でITエンジニアを目指すに至ったのか？
A: 現職の業務効率化のためにExcelマクロを使うようになり、プログラミングが楽しいと感じて仕事にしたいと考えたのが始まりです。当初は、「いつか個人開発や案件で生計を立てられたらいいな」という程度の考えで、転職時期については深く考えずに、趣味レベルで独学を続けていました。しかし、子どもが生まれたことをきっかけに、育休終了後の生活について夫婦で話し合った結果、「リモートワークができる企業への転職」が最適であるという結論に至りました。そこで、自分に合いそうな職種として、セキュリティに強いQAエンジニアというポジションを目指すことにしました。

### Q: 具体的にどのような勤務形態を想定しているか？
A: フルフレックスの原則リモートワークを想定していますが、採用後最初の3ヶ月間を上限として、職場のルールや基本業務をキャッチアップするための期間であれば、出社可能です。それ以降は、子どもの幼稚園の送り迎えのため、原則リモートワークの勤務形態へ移行する必要があります。なお、リモート移行後も、月1回程度の頻度や、事前に調整ができるスケジュールであれば、家族と調整のうえ出社可能です。リモート移行後の普段の働き方としては、例えば、次のような形であれば可能です。

* **5:00 ~ 7:00 2時間勤務**
  (8:30前後に幼稚園送迎)
* **9:00 ~ 13:00 4時間勤務**
  (14:00前後に幼稚園送迎)
* **20:00 ~ 22:00 2時間勤務**
* **合計: 8時間勤務**

なお、14時から20時頃は子どもが家にいるため、業務に専念する時間（勤務時間）にはカウントできないものと考えております。ただし、その時間帯もスマートフォン等での急ぎのご連絡には随時対応可能ですので、チームの業務進行に支障が出ないよう配慮します。子育ての都合で毎日決まって同じ時間に働くことは難しいかもしれませんが、状況に応じて妻や実家のサポートを受けながら、月の総労働時間をしっかりと確保いたします。
